The Power of Pipelining

A simple six-instruction program in textbook notation, run on two machines that share one clock. Each instruction has one colour — follow that colour across its row and watch the same instruction move through the five stages IF → ID → EX → MEM → WB. The non-pipelined machine needs 30 cycles; the pipelined machine needs 10.

With pipelining — 5-stage overlap

Stages overlap: once full, one instruction completes every cycle. Shaded band = all five stages busy at once.

The program — 6 independent instructions

    The five pipeline stages

    • IFInstruction Fetch — read the instruction from memory
    • IDInstruction Decode — read the source registers
    • EXExecute — the ALU does the arithmetic/logic
    • MEMMemory Access — (unused by these register ops)
    • WBWrite Back — store the result in the destination register

    Why there are no stalls

    No instruction reads a register an earlier one writes — every destination and source is different. No loads, no branches. So nothing ever waits: the pipeline fills once (4 cycles) and then never stops.

    Same latency, higher throughput

    Each instruction still takes 5 cycles end-to-end — pipelining does not make one instruction faster. It overlaps them, so more finish per cycle: 3× here, approaching 5× (the number of stages) as the program grows.
